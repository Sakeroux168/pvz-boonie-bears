# 产品定义

## 一句话

一款以《植物大战僵尸》式路线塔防为基础、沿《熊出没》不同动画时期/世界推进剧情，并以角色合成、人物关系、季节机制和 Q 版搞笑演出形成自身玩法特色的同人游戏。

## 核心定位

本项目不是单纯替换 PVZ 素材的换皮版。

核心体验由六根支柱组成：

1. PVZ 式路线塔防：固定路线、格子部署、资源管理、敌人波次与 Boss。
2. 《熊出没》世界时间线：不同动画时期/季作为独立世界，人物关系随世界推进。
3. 战场合成进化：同角色升级 + 指定跨角色融合。
4. 人物关系/羁绊：关系变化会解锁或改变融合、技能和剧情。
5. 世界独有机制：春夏秋冬、森林、小镇、探险、微观等世界必须改变实际玩法，不只换背景。
6. Q 版搞笑互动演出：动作、表情、失败/胜利反馈和角色互动要有明显《熊出没》喜剧感。

## 世界观结构

游戏按《熊出没》电视动画的不同世界/时期组织主线，电影优先作为大型特别世界或支线。

核心人物关系长期推进：

```text
对立
→ 偶尔停战
→ 暂时联手
→ 建立信任
→ 真正友谊
→ 共同守护狗熊岭
```

重要：不同系列的准确官方顺序、角色首次登场和世界边界需要经过资料研究后定稿。未完成来源核验前，任何 Agent 不得自行把网络整理当成正式时间线。

## 第一阶段规模

第一阶段先完成一个可完整游玩的“小世界”：

- 10 关
- 8 名可用角色
- 6 种普通/精英敌人
- 1 个 Boss
- 1 套完整主界面/选关/战斗 UI
- 1 条完整的小世界剧情
- 同角色合成系统
- 少量重点跨角色融合配方
- 至少 1 种世界专属机制

第一阶段目标是验证“好不好玩”，不是一次做完整个《熊出没》时间线。

## 基础战斗循环

```text
查看地图 / 敌人 / 世界规则
→ 选择本关角色卡组
→ 获取资源
→ 部署角色
→ 建立防线
→ 同角色升级或跨角色融合
→ 根据敌人变化改阵
→ 使用角色爆发技 / 羁绊
→ 应对大波与 Boss
→ 获得剧情、角色、融合配方或世界进度
```

## 路线与格子

第一阶段优先保持经典、易理解的多路线格子塔防结构。

默认原型使用 5 条路线和规则化网格；是否最终固定为 5×9，需要在 PoC 和第一世界设计中确认。

后续世界允许在保持“路线防守”核心的前提下变化：

- 水路
- 冰面
- 泥地
- 高地/屋顶
- 小镇道路
- 地下/微观环境
- 特殊阻挡格

## 角色卡组

玩家不会把全部已解锁角色带入一关。

每关开始前根据敌人、地图、天气和 Boss 选择有限卡组。具体携带数量暂未锁定，第一轮设计可从 8 张左右进行测试。

角色设计优先采用“行为差异”，不依赖纯数值区别。

## 角色合成与升级

### 1. 同角色合成

拖动同角色到已经部署的角色上可升级。

例：

```text
熊大 I
单次投掷
+
熊大 I
↓
熊大 II
连续投掷 / 攻击行为升级
```

原则：升级优先改变攻击方式、节奏、范围、控制或表现，而不是只做攻击 +10% / 生命 +10%。

### 2. 跨角色融合

指定角色组合可以融合成新的协作形态，能力必须体现两名角色原本能力的组合。

例：

```text
熊大（远程/指挥） + 熊二（坦克/近战）
→ 兄弟协防形态
→ 熊二承担前线压力，熊大提供远程输出
```

跨角色融合优先表现为“两个角色在一个格子中协同”或“共同形成新机关/战术”，避免为了融合强行把角色变成违和的新生物。

### 3. 剧情锁定融合

角色关系会影响融合配方。

例如熊大与光头强在敌对时期不能融合；当剧情推进到合作/友谊阶段后，才允许解锁对应协作形态。

### 4. 配方规模控制

不要求所有角色两两组合。

第一阶段：

- 8 名角色都支持同角色升级
- 只制作少量高质量指定双人融合
- 三人融合最多做极少数实验配方，甚至可以第一阶段不做
- 未定义专属配方的角色不得自动生成大量低质量组合

### 5. 可逆与容错

融合需要避免一次误操作毁掉整局。

候选方案：

- 合成后短时间可撤销；或
- 支付少量资源拆分。

最终规则在 PoC 后确认。

## 羁绊系统

羁绊优先改变行为，而不是纯数值加成。

例：

- 熊大 + 熊二：熊二被攻击时，熊大触发额外协同攻击。
- 吉吉 + 毛毛：二者共同在场时触发“猴王与跟班”的专属辅助行为。
- 熊大 + 光头强：后期关系解锁机械/投石类协作。

## 角色爆发技

角色可以通过战斗积累能量触发关键技能，用于增加临场操作和救场空间。

第一阶段避免做复杂技能栏，优先“一名角色一个易理解的标志性爆发技”。

## 资源系统

不直接照搬“阳光”名称。

第一阶段研究两层资源是否更好玩：

- 基础部署资源：用于放置角色/普通机关。
- 稀有协作资源：用于融合、爆发技或高价值操作。

名称、产出速度、是否最终保留双资源，需要通过第一世界数值原型确认。

## 世界机制

每个世界至少有一个真正改变决策的玩法机制。

候选方向：

- 春日：春雨、花粉、泥地、蜂群。
- 夏日：水路、酷暑、暴雨、潜水。
- 秋日：风向、落叶、森林火险、丰收资源。
- 冬日：冰面、积雪、暴雪、冻结/滑行。
- 小镇：车辆、道路、屋顶、建筑障碍。
- 探险：护送、追踪、迷雾、保护动物。
- 微观世界：昆虫道路、蜘蛛网、水滴洪水、巨大日用品。

具体机制必须以对应系列资料和游戏性测试为准。

## 敌人设计原则

不能只靠“更多血、更快速度”制造难度。

敌人类型应包括行为差异，例如：

- 正面推进
- 跳过前排
- 偷资源
- 飞行
- 地下突袭
- 护盾
- 指挥/强化周围敌人
- 针对融合或机关的特殊单位

## Boss 设计原则

Boss 不应只是巨大血条。

至少包含：

- 多阶段行为
- 改变战场或路线
- 召唤/机关/特殊规则
- 清晰的角色化演出

## 关卡目标

主线以经典防守为基础，但允许穿插：

- 护送
- 坚守时间
- 保护古树/蜂巢/水源等目标
- 收集任务
- 固定阵容解谜
- Boss 追击/特殊战

避免连续 10 关只有同一种胜利条件。

## 局内与局外成长

### 局内

角色合成、融合、临时强化；关卡结束后重置。

### 局外

优先解锁内容，而不是无限堆数值：

- 新融合配方
- 新被动/技能变体
- 新角色
- 新世界
- 新皮肤/演出
- 图鉴与人物关系内容

## UI / 前端方向

画风：Q 版夸张搞笑。

主界面优先设计为“狗熊岭世界/时间轴地图”，而不是普通功能菜单。

战斗 UI 保持直觉：

- 顶部：资源、角色卡、冷却/状态、暂停。
- 中部：战场与路线。
- 明确展示可融合目标、升级预览和融合结果。
- 世界状态（天气/特殊规则）必须在战斗前和战斗中清晰可见。

## 搞笑演出

角色动作、表情和互动是核心体验，不是最后才补的装饰。

例如低血、技能失败、机械爆炸、角色互怼、胜利/失败都应有角色化反馈。

## 后续模式（非第一阶段核心）

- 无尽模式 / Roguelite 式随机强化
- 特殊挑战
- 每日规则挑战
- 电影特别世界
- 角色关系图鉴

第一阶段不做：

- PvP
- 实时联机
- 开放世界
- 大型装备系统
- 抽卡氪金
- 复杂基地建设

## 资产与版权边界

代码、第三方依赖、字体、音效、音乐、图片和角色素材必须分别记录来源与授权。

当前仓库保持 Private。任何未知授权的素材都不能因为“网上能找到”就直接进入正式资源目录。
