# 第一轮研究任务池

日期：2026-08-23

状态：待执行

本轮研究目标不是直接写游戏，而是给第一世界设计、技术 PoC 和后续正式开发提供可靠依据。

## 研究优先级

### P0-A：《熊出没》官方世界时间线

研究者：Work + Sol

必须回答：

- 电视系列有哪些主要时期/系列？
- 各系列主要发生地点是什么？
- 熊大/熊二/光头强关系在哪些阶段发生明显变化？
- 哪些重要角色在哪些时期成为常驻？
- 哪些季/系列最适合被做成独立塔防世界？
- 电影适合并入主线还是作为特别世界？

要求：每个结论附来源；无法确认的明确标注不确定。

### P0-C：PVZ 与优秀路线塔防机制

研究者：Work + Sol

重点：

- 前几分钟的经济循环
- 卡组限制为什么重要
- 波次如何逐渐施压
- 失败容错
- 精英敌人如何迫使玩家改阵
- Boss 如何避免只是血量变厚
- 地图/世界机制如何改变打法

### P0-D：合成/融合塔防研究

研究者：Work + Sol

重点调查：

- 同单位叠加升级的优点和常见问题
- 跨单位融合如何做到直观
- 如何避免最优配方固定导致其他角色失去价值
- 如何避免“越赢越强”的滚雪球
- 合成是否可撤销/拆分
- UI 如何显示可融合目标和结果
- 如何控制组合数量

### P0-E：GitHub 轮子

每个项目记录：

### P0-F：素材/IP/发布边界

研究者：Work + Sol

只做风险整理，不替代正式法律意见。

重点：

- 同人游戏公开发布与私下自用的差异
- 角色/商标/画面与代码 License 是不同问题
- 网络截图/动画截帧/音乐能否直接作为正式素材
- 字体、音效、BGM 授权
- GitHub 开源代码的 License 义务

## P1：Codex PoC 研究

在产品方向收敛后执行。

### C1 Godot 4.x 最小塔防 PoC

验证网格、拖拽、路线、攻击、敌人、自动测试。

### C2 Fusion PoC

验证 A+A→A2 和 A+B→AB 的数据化配方、拖拽和拆分。

### C3 世界规则 PoC

验证冰面/水路等规则可以作为插件式模块改变战斗，而不复制 Battle Core。
