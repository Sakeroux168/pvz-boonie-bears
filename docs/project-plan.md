# 项目计划与任务分配

日期：2026-08-23

当前阶段：产品定义 + 世界观/角色/融合系统设计 + 技术与开源轮子研究。

## 总原则

先把“什么游戏”定清楚，再决定“怎么实现”。

开发顺序：

```text
产品定义
→ 官方世界观/角色资料研究
→ 开源轮子与技术研究
→ 第一世界玩法/UI/角色定稿
→ 小型 PoC
→ GPT/用户评审
→ Hermes 正式实现
→ Codex 独立审查
→ 用户试玩反馈
```

## 角色分工

| 角色 | 职位 | 主要职责 | 默认不做 |
|---|---|---|---|
| 用户 | 产品负责人 / 总策划 | 提需求、判断好不好玩、最终否决 | 日常编码 |
| GPT-5.6 Sol | 游戏总监 / 美术总监 / 技术评审 | 产品规则、玩法设计、世界/角色/UI审核、技术拍板、PR评审 | 大量重复施工 |
| Work + Sol | 研究负责人 | 官方资料、社区、论坛、GitHub、License、竞品和同人研究 | 未批准即写正式代码 |
| Hermes + Ox Alpha | 主程 / 执行负责人 | 正式实现、运行、测试、修 Bug、工具操作 | 自行改变产品核心方向 |
| Codex | 第二程序员 / PoC / Code Review | 技术 PoC、难 Bug、架构/性能检查、独立代码评审 | 与 Hermes 同时大面积改同一模块 |

## P0：现在立即执行

## P0：GPT + 用户共同完成

### G1 第一世界产品设计

在 Work 的时间线资料完成后，确定：

- 第一世界对应的官方时期
- 10 关剧情节奏
- 8 名可用角色
- 6 种敌人
- Boss
- 世界专属机制

### G2 第一批角色设计

每名角色定：

- 基础定位
- 部署成本区间
- 普通行为
- 同角色 I/II/III 升级表现
- 爆发技
- 羁绊
- 融合候选
- Q 版动作/表情规范

### G3 融合配方表 v1

第一世界只定少量高质量配方。

至少回答：

- 同角色最高几级
- 跨角色融合占几个角色资源
- 融合后是否仍占一个格
- 是否能拆分
- 关系锁定规则
- 融合成本
- UI 如何预览

### G4 UI / 前端设计

先做信息架构，不先做精美成品：

- 主界面
- 世界时间轴
- 选关
- 卡组选择
- 战斗 HUD
- 融合拖拽反馈
- 结算
- 图鉴/关系页

视觉方向：Q 版、夸张、搞笑、角色辨识度高。

## P1：Codex 小型 PoC

只有 P0 产品规则基本定稿后开始。

### C1 引擎 PoC

主候选：Godot 4.x + GDScript。

只验证：

- Windows 开发/运行
- 5 路网格
- 拖拽部署
- 敌人沿路线移动
- 简单攻击
- Headless/自动测试可能性

不做完整关卡。

### C2 Fusion PoC

验证：

```text
A + A → A2
A + B → AB
```

重点：

- 拖拽交互
- 配方数据化
- 结果单位继承/组合行为
- 撤销或拆分
- 不靠大量 if/else 硬编码

### C3 World Rule PoC

验证一个世界规则可以插件式修改战斗，例如冰面/水路，而不复制 Battle Core。

### C4 技术评审报告

Codex 对 PoC 给出：

- 可行性
- 架构风险
- 测试性
- 性能风险
- 推荐/不推荐

输出到 `docs/research/`，不直接改 `docs/decisions.md`。

## P2：Codex 审查职责

Hermes 每完成一个核心模块，由 Codex 做独立审查：

- 是否符合 docs
- 是否有重复/硬编码
- 是否可测试

原则：Codex 优先提修改意见或小补丁，不与 Hermes 同时重写整个模块。

## 美术生产流程

角色立绘/战斗形象暂不让开发 Agent 自由决定。

流程：

```text
用户提出角色/感觉
→ GPT 制定视觉方案/提示词/动作规范
→ 生成或制作概念图
→ GPT 审核角色辨识度、Q版比例、战斗可读性
→ 用户确认
→ 进入正式资产
```

需要分别准备：

- 角色立绘
- 战斗 Idle
- 攻击
- 受击
- 技能
- 融合
- 胜利/失败搞笑演出

第一阶段 PoC 一律允许使用占位图，不因美术阻塞玩法验证。

## 第一里程碑：Playable Prototype

完成标准：

- Windows 可运行
- 5 路基础战场
- 可选卡/部署
- 资源循环成立
- 2 个以上角色
- 2 个以上敌人
- 同角色合成可玩
- 至少 1 个跨角色融合
- 一关可以正常胜利/失败
- 自动或半自动冒烟测试存在

这个里程碑完成前，不批量制作 8 名角色的完整动画资产。
