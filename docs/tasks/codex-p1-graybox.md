# Codex P1｜World 01 灰盒 PoC 任务书

日期：2026-08-23

负责人：Codex

状态：等待产品文档 PR 合并后执行。

## 目的

验证核心玩法与技术假设，不制作正式游戏内容。

PoC 只回答：

1. 5 路参数化棋盘是否好实现、好测试；
2. 拖拽部署是否稳定；
3. 敌人沿固定路线推进、攻击与越线是否清楚；
4. 同角色升级 `A + A → A2` 是否能成为可维护的数据规则；
5. 固定跨角色融合 `A + B → AB` 是否能保留清楚的机会成本；
6. 单资源是否足够支撑部署/升级/融合；
7. GUT 与 GdUnit4 哪个更适合 Windows + headless CI；
8. Godot 4.x 是否值得进入正式实现候选。

## 强约束

- 不使用《熊出没》、PVZ 或任何未知授权素材。
- 全部角色/敌人使用几何形状和功能代号：`unit_a`、`unit_b`、`enemy_basic` 等。
- 不复制 PVZ clone 或无许可证仓库代码。
- 可以阅读已批准研究报告中列出的 MIT/官方示例，但任何实际复制都必须记录来源、commit、文件和许可证。
- 不为了 PoC 搭完整 UI、完整剧情、正式存档或正式美术。
- 不自行把 Godot、GUT、GdUnit4 或其他插件写入 `docs/decisions.md`。

## PoC A：最小 5 路防守

实现：

- 5 条路线；
- 列数来自配置，默认 9；
- 可拖拽一个角色到空格；
- 基础敌人从右向左移动；
- 角色只攻击本路；
- 敌人越过左侧终点触发失败/路线保险；
- 每条路线有一次性灰盒“保险机关”。

验收：

- 改一个配置值即可从 9 列切到 8/10 列；
- 不需要修改核心逻辑；
- 单元位置、路线、占格状态可被自动测试读取。

## PoC B：资源与同角色升级

实现单资源 `resource`。

角色 A：远程持续输出。

规则：

```text
A1 + A1 → A2
A2 + A2 → A3
```

要求：

- A1/A2/A3 数据独立配置；
- 升级改变至少一种行为，不只改伤害数字；
- 升级后不自动把生命和技能状态全部刷新；
- 记录升级前后占格与资源变化；
- 预留短撤销窗口接口，但 PoC 不必做完整拆分系统。

## PoC C：固定跨角色融合

角色 A：远程。

角色 B：前排/近战。

实现：

```text
A + B → AB
```

AB 不是单纯 `A伤害 + B生命`。

最低要求：

- AB 在一个格子内表现为两种角色行为的协作；
- AB 与 A/B 独立铺场相比必须损失一定横向覆盖；
- 拖拽时显示固定结果预览；
- 结果不可随机；
- 数据层能明确查询合法配方。

验收问题：

- 有没有合理局面选择“不融合”？
- 如果没有，记录原因，不要用单纯涨敌人血量修复。

## PoC D：世界目标最小验证

增加一种 `protected_tree` 灰盒目标：

- 占一个格；
- 玩家不能部署；
- 一个特殊敌人可优先攻击它；
- 关卡可定义“至少保住 N 个目标”。

只验证规则与数据边界，不做正式树木美术。

## PoC E：GUT vs GdUnit4

前提：先选定一个明确 Godot 4.x 版本用于试验，不代表正式批准。

对两个测试框架使用**同一批测试样例**：

1. 棋盘 5 路 / 可变列数；
2. 占格冲突；
3. 敌人路线推进；
4. `A1+A1→A2`；
5. 非法升级被拒绝；
6. `A+B→AB`；
7. 非法配方被拒绝；
8. 保护目标胜负条件。

比较：

- License；
- 与试验 Godot 版本兼容性；
- Windows 安装；
- PowerShell/CMD 调用；
- `--headless`；
- 失败退出码；
- JUnit XML；
- 场景/节点测试体验；
- doubles/mocks；
- CI 配置复杂度；
- 插件删除成本；
- 文档与维护状态。

输出二选一建议，但不要直接修改技术决策。

## 推荐目录边界

PoC 允许自行调整命名，但需保持相同职责分离：

```text
src/
  core/       # 纯规则、资源、配方、关卡状态
  battle/     # 战场实体与控制器
  data/       # 单位/敌人/关卡配置
  ui/         # 只做最小调试 UI
  tests/      # 自动化测试
```

核心规则不得直接依赖正式角色美术或剧情节点。

## 交付物

- Windows 启动说明；
- 自动测试命令；
- GUT vs GdUnit4 对比结果；
- 关键架构说明；
- 已知问题；

- 对 Godot 是否进入下一阶段的建议；
- PR，不直接改 main。

## PR 验收标准

只有以下全部成立才算 PoC 完成：

- 5 路与列数参数化；
- 拖拽部署可用；
- 基础敌人推进可用；
- `A+A→A2` 可用；
- `A+B→AB` 可用；
- 保护目标规则可用；
- 至少一套自动测试能在 Windows/headless 跑通；
- GUT/GdUnit4 有同条件对比证据；
- 没有受保护原作素材；
- 没有无许可证代码；
- 没有擅自扩成正式游戏开发。
